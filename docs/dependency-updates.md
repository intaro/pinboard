# Scheduled dependency updates

Runbook for a planned bulk update of everything Pinboard depends on: PHP and JS packages, the pnpm
and Node.js toolchain, Docker base images and Alpine packages, GitHub Actions and QA tools. Doing
all layers in one branch is usually faster than reviewing each Dependabot PR on its own, and it
supersedes those PRs. The binding rules live in [`AGENTS.md`](../AGENTS.md) → "Dependency
Updates"; this page is the how-to.

## Where versions live

| Layer | Source of truth | Also update |
|---|---|---|
| PHP packages | `composer.json` constraints, `composer.lock` | `config/reference.php` (regenerated by Symfony, commit it) |
| Symfony minor | every `symfony/*` `8.x.*` constraint + `extra.symfony.require` | — |
| JS packages | `package.json`, `pnpm-lock.yaml` | — |
| pnpm | `package.json` → `packageManager` | settings in `pnpm-workspace.yaml` |
| Node.js | `.nvmrc` (major only) | `node:<major>-alpine` digests in `Dockerfile.pinboard` and `docker/docker-compose.test.yml` |
| Base images | `Dockerfile.pinboard` (`node`, `composer`, `php`) | `docker/php-fpm/Dockerfile` (`php`, `composer`), `docker/nginx/Dockerfile`, `docker/docker-compose.yml` (`nginx`) |
| Alpine packages | `apk add` fuzzy pins (`=~`) in `Dockerfile.pinboard` | `docker/php-fpm/Dockerfile` |
| Supercronic | `SUPERCRONIC_VERSION` + `SUPERCRONIC_SHA1SUM` in `Dockerfile.pinboard` | `docker/php-fpm/Dockerfile` |
| GitHub Actions | `.github/workflows/*.yml` | — |
| QA hooks | `.pre-commit-config.yaml` (`pre-commit-hooks`, `hadolint`) | — |
| Pinba engine | `xolegator/pinba-engine:<mysql>` tags in `docker-compose.public.yml` and `docker/.env*` | stays on the MySQL LTS line (8.4) |

`grep -rn '@sha256:' Dockerfile.pinboard docker/` lists every pinned digest.

## 1. Prepare

```bash
git switch master && git pull
git switch -c chore/update-dependencies-$(date +%Y-%m)

# Open automated PRs this update should cover
gh pr list -R intaro/pinboard --state open --author app/dependabot

# Bring vendor/ and node_modules/ in line with the lock files first — a stale
# vendor/ makes `composer outdated` and the baseline checks lie.
composer install --no-interaction
CI=true pnpm install --frozen-lockfile   # CI=true: no TTY prompt if node_modules must be rebuilt
```

Run the full check set (section 4) **before** changing anything and write down the result, so an
existing failure is not mistaken for a regression.

## 2. Inventory what is new

```bash
composer outdated --locked            # all packages, incl. transitive majors
pnpm outdated
npm view pnpm dist-tags.latest        # pnpm itself
curl -fsSL https://nodejs.org/dist/index.json | jq -r '.[] | select(.lts) | "\(.version) \(.lts)"' | head -3

# GitHub Actions and hooks: latest release + commit SHA (annotated tags are dereferenced)
for r in docker/setup-buildx-action docker/build-push-action docker/login-action \
         shivammathur/setup-php codecov/codecov-action googleapis/release-please-action \
         pre-commit/pre-commit-hooks hadolint/hadolint; do
  t=$(gh api repos/$r/releases/latest --jq .tag_name)
  read -r type sha < <(gh api repos/$r/git/ref/tags/$t --jq '.object.type+" "+.object.sha')
  [ "$type" = tag ] && sha=$(gh api repos/$r/git/tags/$sha --jq .object.sha)
  echo "$r $t $sha"
done
# First-party actions track major tags; check whether a new major exists:
gh api repos/github/codeql-action/git/matching-refs/tags/v --jq '.[].ref' | grep -E 'tags/v[0-9]+$'

# Base image digests
for i in node:24-alpine composer:2 php:8.5-fpm-alpine nginx:1.30-alpine; do
  docker pull -q $i >/dev/null && docker image inspect $i --format '{{index .RepoDigests 0}}'
done

# Alpine package versions actually available to the runtime image
docker run --rm php:8.5-fpm-alpine sh -c 'apk update -q >/dev/null; for p in bash curl icu-dev libxslt-dev nginx oniguruma-dev supervisor tzdata git libzip-dev unzip zip; do apk policy $p | sed -n 2p | sed "s/^ */$p /"; done'

gh release view -R aptible/supercronic   # release notes contain the SHA1 per binary
```

Choosing targets:

- Stable releases only. Node.js: the current **Active LTS** major, not "Current".
  PHP / MySQL / nginx: the lines the project already uses unless the update is the point of the
  work (nginx: even minor = stable).
- A release published less than a day ago is skipped on purpose (`minimumReleaseAge`); take the
  newest version that is at least 24h old.

## 3. Update layer by layer

### PHP

```bash
composer update --with-all-dependencies
```

- Read the `Upgrading x (a => b)` lines: a **major** bump of a transitive package (e.g.
  `doctrine/collections 2 → 3`) still needs its `UPGRADE.md` checked against `src/`.
- For every package that moved a minor or major, read `vendor/<vendor>/<pkg>/UPGRADE.md` and the
  upstream `UPGRADE-x.y.md` / `CHANGELOG.md`, then grep `src/`, `config/`, `migrations/` and
  `tests/` for each deprecated API.
- Deprecations must be zero in every environment:
  `APP_ENV=dev php bin/console debug:container --deprecations` (repeat with `APP_ENV=test`).
- `config/reference.php` is regenerated by Symfony when bundle configuration changes — commit it.
- `composer audit`, `composer validate --strict`.
- Flex recipe drift (`composer recipes`) touches `config/`; review it in a separate PR with
  `composer recipes:update <package>`, not inside the bulk update.

### JavaScript

```bash
CI=true pnpm update --latest
pnpm audit
```

Compare the `public/build/` file names before and after `pnpm build`: unchanged content hashes of
the vendor chunk and CSS mean the bundle output did not change.

### pnpm itself

1. Read every major's release notes (`gh release view v<N>.0.0 -R pnpm/pnpm`).
2. Set `packageManager` to the new version and install through corepack, as CI and Docker do:
   `COREPACK_ENABLE_DOWNLOAD_PROMPT=0 corepack pnpm install --no-frozen-lockfile`.
3. pnpm 12+ **fails** on keys in `pnpm-workspace.yaml` it does not recognise — any error here must
   be fixed, not ignored.
4. `pnpm-lock.yaml` must stay a single YAML document: `grep -c '^---$' pnpm-lock.yaml` must print
   `0`. See "Known pitfalls" for why `pmOnFail: ignore` is set.
5. Run `corepack pnpm update` once so the new version re-resolves the lockfile now instead of
   inside the next Dependabot PR.

### Docker images and Alpine packages

- Replace every digest (never drop one). Tags stay on the chosen line (`node:24-alpine`, …).
- `apk` pins are fuzzy (`curl=~8.22`): bump the pinned feature version when Alpine ships a new
  one — **the old pin fails the build as soon as the live repository moves on**, even with an old
  base digest.
- Supercronic: take the SHA1 from the release notes, then verify it yourself:
  `curl -fsSL <url> | sha1sum`.
- Lint with the hadolint version from `.pre-commit-config.yaml`:
  `docker run --rm -i hadolint/hadolint:<ver> < Dockerfile.pinboard` (and the other Dockerfiles).

### GitHub Actions and QA tools

- Replace SHA **and** the trailing `# vX.Y.Z` comment; first-party actions stay on `@vN`.
- `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest`
- New hook versions may add rules (hadolint 2.15 added DL3066) — run them over the whole repo.

## 4. Verify

Run everything, compare with the baseline from step 1.

```bash
export XDEBUG_MODE=off
php  vendor/bin/phpunit --no-progress            # PHP 8.4
php8.5 vendor/bin/phpunit --no-progress          # PHP 8.5 (see pitfalls: local pinba extension)
vendor/bin/php-cs-fixer fix --dry-run --diff
APP_ENV=dev APP_DEBUG=1 php bin/console cache:warmup
vendor/bin/phpstan analyse --no-progress --memory-limit=1G
php bin/console lint:twig && php bin/console lint:container && php bin/console lint:yaml config
pnpm build

make test && make test-down                      # dev image build + all checks in containers
```

Production image and stack — the same gate as CI `Docker image + stack smoke test`. Use a separate
env file and ports: the CI job overwrites `.env`, which is a tracked file locally.

```bash
S=$(mktemp -d)
docker build -f Dockerfile.pinboard -t xolegator/pinboard:local-smoke .
{ echo "APP_SECRET=$(openssl rand -hex 32)"; echo "MYSQL_ROOT_PASSWORD=Loc#Smoke-Root1"
  echo "DB_PASSWORD=Loc#Smoke-App1"; echo "PINBOARD_TAG=local-smoke"
  echo "PINBOARD_HTTP_PORT=18080"; echo "MYSQL_PORT=23306"; echo "PINBA_UDP_PORT=30012"; } > $S/smoke.env
DC="docker compose -p pinboard-smoke --env-file $S/smoke.env -f docker-compose.public.yml"
$DC up -d --wait --wait-timeout 300
curl -fsS -o /dev/null http://127.0.0.1:18080/login
docker exec pinboard-web php bin/console add-user smoke@example.com SmokeCi123 ROLE_ADMIN
docker exec pinboard-aggregate php bin/console aggregate --no-interaction
docker logs pinboard-web 2>&1 | grep '"channel":"deprecation"'   # compare with the previous release
$DC down -v
```

The server pages are not covered by PHPUnit. To exercise them, send real Pinba packets (needs a
local PHP with the `pinba` extension), aggregate, log in and open
`/<server>/<host>/overview.html`, `timers`, `statuses`, `req-time`, `mem-usage`, `cpu-usage` and
`live`:

```bash
php8.5 -d pinba.enabled=1 -d pinba.server=127.0.0.1:30012 -r '
  pinba_server_name_set("smoke.example"); pinba_hostname_set("smokehost");
  pinba_script_name_set("/page"); $t = pinba_timer_start(["group" => "db::query"]);
  usleep(1000); pinba_timer_stop($t); pinba_flush();'
```

## 5. Reconcile open Dependabot PRs

For every open Dependabot PR compare its target versions with the branch
(`gh pr view <n> -R intaro/pinboard`, `gh pr diff <n> -R intaro/pinboard`). Covered means the
branch has the same or a newer version of every package in the PR. List any gaps in the PR
description. Dependabot closes superseded PRs itself once the update is merged into `master`;
close the rest with a comment linking the bulk PR.

## 6. Commit and PR

Split commits by layer so each can be reviewed (and reverted) on its own:
PHP / JS + pnpm / Docker / GitHub Actions + QA hooks / docs.

Commit type follows [releasing.md → "Version discipline"](releasing.md):

- Routine bumps of runtime dependencies → `chore(deps): ...` (ride the next release).
- The shipped image needs rebuilding (base-image security fixes, a broken `apk` pin, a runtime
  package with an advisory) → `fix(deps): ...` or `fix(docker): ...`, which cuts a release.
- Actions → `ci: ...`; hooks and dev-only images → `build: ...` / `chore: ...`; runbook → `docs: ...`.

## Known pitfalls

- **Stale `vendor/`.** A local `vendor/` behind `composer.lock` makes `composer outdated` report the
  wrong baseline. Always `composer install` before inventorying.
- **Local PHP with the real `pinba` extension.** `tests/Unit/Stopwatch/StopwatchTest` relies on the
  stub in `stubs/pinba.php`, which is loaded only when the extension is absent. With the extension
  installed (e.g. the local `php8.5`), two tests error with
  `Call to undefined function ...pinba_test_reset()`. CI and `make test` have no extension and pass.
- **`apk` pin rot.** Alpine drops superseded package versions from its live repository; an exact
  pin (`pkg=1.2.3-r0`) — and a fuzzy pin one feature version behind — breaks the image build.
- **pnpm 12 lockfile layout.** With a `packageManager` pin and the default `pmOnFail: download`,
  pnpm 12 writes its own resolution into a leading YAML document of `pnpm-lock.yaml`. GitHub's
  dependency graph reads only that first document, so every npm dependency disappears from it and
  Dependabot security alerts stop (dependabot/dependabot-core#15904, pnpm/pnpm#13805).
  `pmOnFail: ignore` in `pnpm-workspace.yaml` keeps the lockfile single-document; corepack still
  enforces the pinned version. Consequence: run pnpm through corepack (`corepack enable`) locally,
  a globally installed pnpm no longer switches versions by itself.
- **pnpm 12 strict release age.** Since pnpm 12.3 an explicit `minimumReleaseAge` makes
  `minimumReleaseAgeStrict` default to `true`, which breaks every Dependabot npm update with
  `ERR_PNPM_STRICT_MIN_RELEASE_AGE_REQUIRES_SAVE` (dependabot/dependabot-core#16375). It is set to
  `false` explicitly. Dependabot's own default cooldown (3 days) is longer than the 24h pnpm window,
  so it does not propose versions pnpm would reject.
- **New lint rules in tool updates.** hadolint 2.15 added DL3066 (numeric `USER`). The runtime image
  now uses `USER 82:82`, the uid/gid of `www-data` in the `php:*-alpine` base.
- **Vendor deprecations in logs.** `doctrine/migrations` 3.9.7 logs
  `Table::addColumn is deprecated` with DBAL 4.5 while creating its metadata table. It comes from the
  vendor code and needs an upstream `doctrine/migrations` release; nothing to change in Pinboard.
